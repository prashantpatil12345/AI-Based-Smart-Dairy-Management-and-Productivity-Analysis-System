## Final architecture

### Training and standalone classifier

```text
Cattle_Resized/ (class folders)
        ↓
ml/src/data/prepare_dataset.py
  validate images → stratified train/val/test manifests
        ↓
ml/src/utils/manifests.py + ml/src/data/transforms.py
  Dataset/DataLoader + train augmentation/eval preprocessing
        ↓
MLP | CNN | ResNet-50 | ViT-B/16
        ↓
ml/src/training/Trainer + callbacks
  train → validation → best validation-loss checkpoint
        ↓
ml/src/evaluation/
  test metrics, reports, plots, training histories
        ↓
Expected exported checkpoint: models/<model>_best.pth
        ↓
FastAPI backend → JSON prediction + breed metadata
```

The checkpoint export is described by the comparison notebook code, but no checkpoint is present in this local checkout. The live hosted service currently reports a loaded ViT v2.0.

### SmartDairy image-prediction and confirmation path

```text
SmartDairy user selects image
  → upload to Supabase Storage bucket "breed-uploads"
  → create signed URL (1 hour)
  → authenticated supabase.functions.invoke("breed-recognition",
       { image_url: signedUrl })
  → Edge Function checks user/rate limit and fetches signed image
  → multipart POST field "file" to hosted /predict/file
  → map classifier breed/confidence; insert breed_predictions row
  → return prediction_id, breed, confidence, reasoning
  → UI allows breed confirmation
  → confirm-breed updates breed_predictions.confirmed_breed
       and optionally cattle.breed
```

The first part and database writes are verified from current source. No direct browser call to the classifier is made by `BreedRecognition.tsx`. The Edge Function request has no configured timeout. The remote Supabase deployment version was not queried.

### Preparation, split and preprocessing

`ml/src/data/prepare_dataset.py`:

1. Walks class folders and considers `.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp`, `.tiff`.
2. Opens and verifies each candidate image; records relative path, class, dimensions, color mode and file size for valid images.
3. Writes corrupt-image details only if any corrupt files are found. Current image validation found zero.
4. Uses two stratified `train_test_split` calls with seed `42`, configured ratios 70%/15%/15%.
5. Writes `train.csv`, `val.csv`, `test.csv`, `all.csv`, and a class-balance report when run.

Current committed/generated manifest sizes:

| Split manifest | Images | Classes | Per-class min–max |
|---|---:|---:|---:|
| `ml/artifacts/manifests/train.csv` | 2,139 | 26 | 25–175 |
| `ml/artifacts/manifests/val.csv` | 458 | 26 | 6–37 |
| `ml/artifacts/manifests/test.csv` | 459 | 26 | 5–38 |
| `ml/artifacts/manifests/all.csv` | 3,056 | 26 | all records |

`ml/src/data/transforms.py` applies training-only random resized crop (scale 0.8–1.0, ratio 0.9–1.1), horizontal flip (p=0.5), rotation (±15°), and color jitter (strength 0.2; hue 0.1). Both train and evaluation paths convert to tensor and normalize with ImageNet mean `[0.485, 0.456, 0.406]` and standard deviation `[0.229, 0.224, 0.225]`. Evaluation/inference resizes to 224×224 without augmentation.

`ml/src/utils/manifests.py` derives `class_to_idx` from sorted unique training labels. The training DataLoader shuffles and drops the final incomplete train batch; validation/test do not shuffle. It uses `pin_memory=True`; there is no weighted sampler or duplicate-removal stage.

## FastAPI backend

`backend/app/main.py` creates the app, installs permissive CORS from settings, loads the inference and breed-info singletons during startup, and includes health, prediction and metadata routers. If `frontend/dist/` exists, FastAPI serves it at `/` and serves its assets; otherwise `/` returns API name/version/docs metadata. `/docs` and `/redoc` are enabled.

| Method | Endpoint | Purpose | Input | Output | Used by |
|---|---|---|---|---|---|
| GET | `/` | Root/API landing; serves built SPA if present | None | HTML or JSON info | Browser/root check |
| GET | `/health` | Liveness/model status | None | `status`, `model_loaded` | Health check |
| GET | `/version` | Runtime model/API labels | None | app name/version, model version/name, loaded class count | Version check |
| POST | `/predict/file` | Predict uploaded image | Multipart `file`; optional `top_k` query 1–10, default 3 | `PredictResponse` | Standalone frontend and SmartDairy Edge Function |
| POST | `/predict/url` | Predict image fetched by backend | JSON `{url, top_k}` | `PredictResponse` | Standalone frontend |
| POST | `/predict/base64` | Predict encoded image | JSON `{image, top_k}` | `PredictResponse` | Standalone frontend |
| GET | `/breeds` | List metadata with optional filters | Optional `animal_type`, `search` query | `{total, breeds:[...]}` | Standalone breed explorer |
| GET | `/breeds/{breed_name}` | Get breed detail | URL path breed name | `BreedDetail` or 404 | Standalone breed explorer |
| GET | `/docs`, `/redoc` | FastAPI-generated docs | None | OpenAPI UI/docs | Developers |

Prediction request handling checks that the model is loaded (503 otherwise), decodes the image, calls inference, enriches with breed metadata when an exact name matches, and returns the response schema. Invalid image/URL input is generally 400; unexpected inference errors are logged and returned as 500 with a generic prediction-failed detail. The API has no application-level authentication. CORS defaults to `["*"]`.

`image_loader.py` converts uploads, URL downloads, and base64 input to RGB PIL images. URL fetching has a configured timeout and checks the advertised content length against the 10 MB default, but uploaded-file size is not explicitly capped in this route. The code accepts HTTP(S) URLs and does not restrict remote hosts.

`inference.py` loads the checkpoint on startup, chooses CPU/CUDA/MPS, reconstructs one of the four architectures for state-dict checkpoints, and runs eval mode. Input is resized to 224×224, converted to tensor, ImageNet-normalized, passed through the model, softmaxed, and top-k selected. Confidence is a 0–1 probability. It adds low/moderate warnings below 0.5/0.75. `predict.py` formats optional breed metadata and model-version fields.

`ml/src/inference/predictor.py` is a second reusable inference implementation; the FastAPI endpoints do **not** call it. The backend has its own `services/inference.py` and `services/image_loader.py`. This is a duplicate/parallel inference path rather than one shared service.

## Breed metadata

`data/breed_metadata.csv` contains 26 records and 11 columns:

`breed_id`, `breed_name`, `animal_type`, `region`, `avg_milk_liters_per_day`, `lifespan_years`, `primary_use`, `coat_color_notes`, `horn_notes`, `description`, `source_reference`.

All 26 metadata names exactly match the dataset names; there are no missing or extra metadata records. Metadata records identify 20 as Cow and 6 as Buffalo. The IDs are one-based and follow the same alphabetical order as the model class list, offset by one.

`backend/app/services/breed_info.py` loads the CSV into an in-memory dictionary keyed by exact `breed_name`; the prediction response uses the exact classifier output for lookup. `/breeds/{breed_name}` tries exact lookup, then case-insensitive substring search. The API prediction summary includes breed name, animal type, region, milk yield, lifespan, primary use and description. The independent ML utility `ml/src/data/breed_metadata.py` provides a similar but separate loader and summary implementation.

## SmartDairy integration

The parent SmartDairy implementation currently present in source is:

1. `src/pages/BreedRecognition.tsx` uploads the file to the `breed-uploads` Storage bucket under the user's ID.
2. It makes a signed URL valid for 3,600 seconds.
3. It invokes `supabase.functions.invoke("breed-recognition", { body: { image_url: signedUrl } })`.
4. `supabase/functions/breed-recognition/index.ts` validates POST/body/URL protocol, authenticates the Supabase user, checks/logs a 5-per-minute user rate limit, downloads the image bytes, then sends multipart field `file` to `https://sajit9285-cattle-breed-classifier.hf.space/predict/file`.
5. The classifier response requires a non-empty `predicted_breed` and finite confidence in [0,100] (0–1 values are scaled to percentage). Top-k, metadata description, warning and model version may be folded into `reasoning`.
6. It inserts `user_id`, `image_url`, normalized `predicted_breed`, percentage `confidence`, and `reasoning` into `breed_predictions`, then returns `{prediction_id, breed, confidence, reasoning}`.
7. `confirm-breed` writes `confirmed_breed` and optional `cattle_id` to `breed_predictions`; if a cattle ID is supplied it updates `cattle.breed`.

**Authentication/security:** the browser uses Supabase Auth for the Edge Function call; the function verifies the user via `auth.getUser()`. The classifier call is server-to-server and the hosted API is public; no classifier API key is configured or sent. Supabase environment variable names are `SUPABASE_URL` and `SUPABASE_ANON_KEY`; values are intentionally not included here.

**Error handling:** the Edge Function responds with 401 for missing/invalid auth, 429 on the rate limit, 400 for invalid URL/image fetch/empty data, 503 when it cannot reach the classifier or classifier returns 5xx, and 502 for classifier non-5xx HTTP failures or invalid/malformed prediction responses. It returns 500 for persistence/other failures. There is no explicit timeout on the image or classifier `fetch`.

**Confidence/top-k:** the hosted API returns confidence on a 0–1 scale (the Edge Function handles either fraction or percentage); the Edge Function stores and returns percentage. It accepts at most three well-formed top-k items for reasoning, but does not return `top_k` or `breed_info` as separate UI fields. The UI uses its local breed catalog as metadata fallback.

**Current versus old/legacy:**

- The current `BreedRecognition.tsx` inference call is to the Supabase `breed-recognition` Edge Function. There is no browser call to `/api/breed-predict`.
- The Edge Function source points to the Hugging Face classifier above and no longer makes a Roboflow primary inference call.
- The separate parent-project `ml-service/` still contains `/api/breed-predict` and Roboflow code using `cattle-breed-wtkzl/2`; it is not invoked by the current breed page source.
- Comments and user-facing copy in `BreedRecognition.tsx` still mention Roboflow, and the no-data error mentions a Roboflow prediction server. This is stale text, not evidence of a current Roboflow call.
- A SmartDairy landing-page description mentions Gemini vision, and a Lovable auth integration file remains elsewhere in the parent project. Those references are not the classifier call path inspected here.
- The Edge Function source was changed to use the hosted ViT in the earlier project work and was not deployed in that work. Current deployed Supabase function code is **not verified**; source and remote deployment must not be treated as identical without checking.
